# 检索评估框架与指标设计说明

> **定位**：本文说明 `wealth-rag` 检索模块的评估集、指标、统计方法与消融实验设计。
> 对应问题档案中的 **P0-7（评估集失效）**。
>
> **一句话结论**：旧指标（文档级 Recall@10）**恒定 1.000、对切分完全失敏**，是 15 个问题
> 被掩盖 5 天的直接原因；本文档给出替代方案，并已在真实索引上跑通首轮基线与重排消融。

---

## 1. 为什么必须重建评估

### 1.1 旧指标失效的机制

原 `evaluation.py` 只比对 `doc_id` / `doc_title` / `source_path` 做**文档级**判定，
而全库只有 **6 篇文档**。于是「top-10 里出现任意一个来自正确文档的块即算命中」——
即使切分完全错乱也必然命中。实测**恒为 1.000**。

**根因不是"评估集太小"，而是"评估粒度与优化粒度不匹配"**：系统优化的是 chunk
（切分策略、面包屑、父子块），评估的却是 document。

### 1.2 指标失效比没有指标更危险

没有指标时人会保持警惕；有一个恒为 1.000 的指标，反而会制造「系统已经很好」的
虚假信心。这正是 P0-1~P0-6（页眉污染、目录入库、标题丢失…）能潜伏 5 天的原因。

## 2. 评估集设计

### 2.1 规模与构成

| 项目 | 取值 |
| :--- | :--- |
| 总条数 | **70**（可答 63 / 不可答 7） |
| 文件 | `eval/queries.jsonl` |
| 类别 | 事实 12 · 定义 14 · 枚举 20 · 程序 9 · 数值 5 · 表格 2 · 对比 1 · 负例 7 |

**为什么是 70 条而不是 500 条**：比例型指标在 n 条查询下的 95% 正态近似置信区间半宽
≈ 1.96·√(0.25/n)，即 **n=50 → ±13.9pp、n=100 → ±9.8pp**。这意味着 50–100 条规模下
"两配置差 3 个点"**统计上无意义**。与其堆数量，不如把每条标对、并统一报告置信区间。

> 论文侧的量级参照：ARES 把**约 150 条人工标注**定为 PPI（prediction-powered inference）
> 的最低要求，实验用 300 条。

### 2.2 标注粒度：锚 `heading_path`，**不锚 `chunk_id`**

这是设计中最重要的一条决策。

| 锚点 | 稳定性 | 后果 |
| :--- | :--- | :--- |
| ~~`chunk_id`~~ | ❌ 脆 | 改 `max_tokens` / `overlap` / 切分器版本即整体失效——**而切分恰恰是要被测的对象** |
| ✅ `heading_path` | ✅ 稳定 | 重新切分后同一份评估集仍然可用 |

匹配规则：`gold` 归一化后出现在结果的 `heading_path` 归一化串中即为命中。例如
`gold = "二、 人民币防伪特征"` 命中
`金融知识普及读本 > 第一章 人民币 > 第二节 人民币防伪与反假 > 二、 人民币防伪特征`。

> 这也解释了为什么 `heading_path` 值得在切分阶段投入——它同时是**检索信号**与**评估锚点**。

### 2.3 不做池化标注（穷举判断）

TREC 式 pooled judgments 只对「某参赛系统 top-k 返回过的文档」做判断，这直接产生
**pool bias**：召回池外文档的系统无法被正确打分。

本语料只有 **664 个子块**，小到可以**穷举判断**，从根上消除该偏差（Cranfield 经典
设置同样是穷举判断）。因此评估集**独立于当前检索链路**——这对"测切分改动"是必需的，
否则一改切分，评估集既失效又偏向旧配置。

### 2.4 负例分层

不可答查询**必须对抗式人工撰写且形似可答问题**——SQuAD 2.0 明确批评了
"automatically generated unanswerable questions that are easy to identify" 的做法
（其 50,000+ 条无答案问题是人工刻意写成类似可答问题的）。

本评估集的 7 条负例覆盖三档：

| 档位 | 例子 | 考察点 |
| :--- | :--- | :--- |
| **weak**（域外） | 「什么是量子纠缠」「如何用 Python 计算夏普比率」 | 是否会把域外问题硬套到金融语料 |
| **strong**（同域未覆盖） | 「股票开户需要办理哪些手续」「2024 年最新的 LPR 报价」 | 最接近真实幻觉场景 |
| **切分负例** | 「这本书的目录里一共列了多少章」（`must_not: 目录`） | 目录页/页眉是否复发 |

`must_not` 是显式断言「这类块不该出现在结果里」。**当前它匹配不到任何块**——
因为目录页已被 P0-2 修复剔除。这不是错误，而是**目标状态**；保留它是为了在回归时
立刻发现污染复现（`eval/validate_queries.py` 会把它报为「信息」而非「失败」）。

## 3. 指标设计

### 3.1 检索质量（可答查询，n=63）

| 指标 | 定义 | 适用边界 |
| :--- | :--- | :--- |
| **Hit@k** | top-k 内是否命中任一 gold（二值） | 最粗最稳，适合当**回归红线**；k 大时易饱和 |
| **Recall@k** | 被覆盖的 gold 标注数 / gold 总数 | 集合度量、**对排序不敏感** |
| **Precision@k** | 命中的相关块数 / k | 反映下游上下文纯度；IR Book 称其为"最不稳定的常用指标" |
| **MRR@k** | 首个命中排名的倒数 | 位置敏感；但只看首个，多可接受块场景会**低估** |
| **nDCG@k** | 二值增益的位置折扣累计 | **位置敏感**，重排的主指标 |
| **MAP@k** | 平均精度 | 位置敏感、判别力强；需要**完整**相关集合 |

> **Recall 的分母必须是「gold 标注条数」而非「命中的块数」**。开发中曾因此得到
> `Recall@10 = 1.29 > 1` 的荒谬值——同一小节常被切成多个子块，两个量的单位不同。

### 3.2 ⚠️ 重排场景的核心陷阱：k 与 W 的关系

设重排输入候选集为 `R`（`|R| = W`，即 `config.retrieval.fused_top`）。重排器**只重排 R、
不改变 R**。于是：

- 若报告的 **k = W**，则"前 k 名"恒等于 `R` → **Recall@k 对重排完全不敏感**，
  重排的边际收益在数学上必然显示为 0；
- 若 **k < W**，Recall@k 会变，但被 **Recall@W（第一阶段候选召回率）硬性封顶**。

**本框架的应对**：
1. 报告位置敏感指标（nDCG@k / MRR@k / MAP@k）为主；
2. 单独输出 **`Recall@W` 作为"回召率上限"**（当前配置 W=20、k=10）；
3. 若 `Recall@W` 本身偏低，**先修第一阶段，不要调重排**。

> 工程锚点：Anthropic 的 Contextual Retrieval 用第一阶段 **top-150**、重排后 **top-20**，
> 并报告试过 5/10/20 后认为 20 最优。

### 3.3 多粒度（父子块）指标

父子块系统有**两类失败**，混在一个指标里无法归因：
(a) 子块未召回；(b) 子块命中但父块回查失败/错配。本框架分离出：

| 指标 | 定义 | 诊断目标 |
| :--- | :--- | :--- |
| **父块回查成功率** | 成功取到 `parent_text` 的块 / 带 `parent_id` 的块 | 掉下来 = 父子映射或回查链路坏了，**与召回质量无关** |
| **同父冗余度** | 1 − 去重父块数 / 带 `parent_id` 的块数 | 接近 1 = 命中挤在同一节的多个子块（`dedupe_by_parent` 要治的问题） |

> 后续可加：`ParentCoverage@k`（命中子块覆盖的 gold 父块比例）——本系统父块仅 109 个，
> 可**全量人工标注父子映射**，从而把该项做成真正带 gold 的指标。

### 3.4 拒答 / 无答案检测

把 `low_confidence` 视为一个**二分类器**，而非"顺带的一个布尔字段"：

| 指标 | 定义 | 当前 |
| :--- | :--- | :--- |
| **误拒率 FRR**（可答） | 可答查询被标 `low_confidence` 的比例 | 0.0159（1/63） |
| **拒答准确率**（不可答） | 不可答查询被标 `low_confidence` 的比例 | 0.7143（5/7） |

> 单一 accuracy 会被无答案 query 的占比严重扭曲（本例只有 7/70）。**建议后续升级为
> 阈值扫描下的 risk–coverage 曲线 + AUC**：`no_answer_threshold` 是一个可调旋钮，
> 只报单点无法知道"调高阈值会拒掉多少可答问题"。

### 3.5 切分质量的直接指标

端到端检索指标无法区分"切分不好"与"检索算法不好"。建议同时监控（本框架的
`docs/audit/verify_fix.py` 已实现前两项）：

| 指标 | 当前值 | 说明 |
| :--- | :--- | :--- |
| **标题覆盖率** | 100%（`raw_text` 含叶子标题） | 证据文本是否自带定位信息 |
| **面包屑深度分布** | 深度 1 仅 0.6% | 层级是否真的建立起来 |
| **污染块数** | 目录 0 / 页眉污染 4（均为文档级引言） | 导航元数据是否被剔除 |
| **纯噪声块** | 0 | 续表/页码/图片占位是否入库 |

> 前沿工作 **HOPE**（Holistic Passage Evaluation, SIGIR 2025）把切分质量分为
> intrinsic / extrinsic / passages–document coherence 三层，其关键结论是
> **"passage 之间的语义独立性"比"passage 内概念统一"更重要**——
> 这**挑战了本项目"按 `heading_path` 追求概念统一"的隐含假设**，值得用自完备性
> （只给该块，能否回答它对应的问题）另做一组诊断。

## 4. 统计严谨性

### 4.1 必须报置信区间

所有指标均输出 **percentile bootstrap 95% CI，按 query 重采样**（不是按块）。
小样本下单个均值没有意义——无法区分"真的变好"与"评估集里恰好有几条难 query"。

### 4.2 A/B 比较必须**配对**

所有配置在**同一批 query** 上评测，query 难度是共同方差。配对检验先算每 query 的
`d_i = metric_A(q_i) − metric_B(q_i)`，再对 `d` 做检验，**消掉 query 主效应**，
功效显著高于比较两个均值。

本框架实现**配对 bootstrap**（符号翻转重采样，5000 次）：

```powershell
python -m wealth_rag.evaluation --no-rerank --json eval/runs/no_rerank.json
python -m wealth_rag.evaluation --compare-with eval/runs/baseline.json
```

### 4.3 多重比较

6 个配置 = 15 组两两比较，直接比 p < 0.05 会有大量假阳性。**预先指定单一 baseline、
只做 baseline-vs-others**，或对 p 值做 Holm / Bonferroni 校正。

## 5. 消融实验设计

### 5.1 冻结变量

每次 run 必须记录：语料快照、切分器版本、评估集版本、随机种子、W、k 集合。
缺任一项，两次 run 就不可比。

### 5.2 分层顺序（只动一件事）

| 层 | 只变什么 | 主指标 | 为什么放这个位置 |
| :--- | :--- | :--- | :--- |
| ① **切分层** | 切分策略（其余固定） | 块级 nDCG + 切分诊断指标 | **唯一能证明"切分改动有效"的实验** |
| ② **父子映射层** | 「命中子块→回查父块」规则 | 父块回查成功率 / 同父冗余度 / nDCG | 与召回解耦 |
| ③ **召回层** | dense-only / sparse-only / RRF | 各自 `Recall@W` | 同报上限，避免把"深度变化"误读为"融合收益" |
| ④ **重排层** | rerank on/off（**同 W**） | nDCG@k / MRR@k | 只有位置敏感指标能反映重排 |
| ⑤ **拒答阈值层** | `no_answer_threshold` 扫描 | FRR / 拒答准确率 | 单独在无答案集上做，不与上面混一张表 |

> **耦合陷阱**：关掉一路召回时，另一路的候选深度必须保持不变，否则测到的是"深度变化"
> 而不是"融合收益"。

### 5.3 报告格式

每个配置一行，**缺任一列都会导致过度解读**：

`nDCG@10` ｜ `其 bootstrap 95% CI` ｜ `Δ vs baseline` ｜ `Δ 的配对 CI` ｜ `配对 p 值` ｜
`Recall@W（上限）` ｜ `MRR@10`

### 6.1 首个消融：重排是否有效

| 配置 | MRR@10 | nDCG@10 | MAP@10 | Hit@10 | Recall@10 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| rerank **开** | 0.9299 | 0.9474 | 0.9299 | 1.0000 | 1.0000 |
| rerank **关** | 0.8733 | 0.9036 | 0.8706 | 1.0000 | 1.0000 |
| **Δ** | **+0.0566** | **+0.0438** | **+0.0593** | 0 | 0 |

> 这张表本身就是**评估框架价值的最好证明**：`Hit@10` 与 `Recall@10` 在两次运行中
> **完全相同**，只有位置敏感指标（MRR/nDCG/MAP）能反映重排收益。
> 若沿用旧的文档级 Recall，这个 +0.057 的改进**完全不可见**。

### 6.2 已知短板（基线暴露的问题）

| 现象 | 明细 | 下一步 |
| :--- | :--- | :--- |
| **拒答失败 2/7** | `q067` 目录陷阱、`q070` 不当请求未被判低置信 | 前者说明 `no_answer_threshold` 对"目录类"问法无效（目录已删，系统返回了别的块）；后者属策略问题，可在编排层拦截 |
| **误拒 1/63** | `q061 什么是定投` | 「定投」在语料中只作为 `二、长期投资纪律` 的一个从句出现，属**语料覆盖问题**而非检索问题 |
| `Hit@10` 饱和 | 1.0000 | 后续以 `Hit@3` / `MRR` / `nDCG` 为主指标 |
| 评估集规模 | 70 条 | 目标扩到 80–120 条，并把负例提到 20–30% |

## 7. 使用方法

```powershell
# 0) 先校验标签（写错 gold 会让「检索失败」与「标签错误」无法区分）
python eval\validate_queries.py

# 1) 基线 & 消融（--json 落盘逐条结果，供配对检验）
python -m wealth_rag.evaluation --queries eval/queries.jsonl --top-k 10 --json eval/runs/baseline.json
python -m wealth_rag.evaluation --queries eval/queries.jsonl --top-k 10 --no-rerank --json eval/runs/no_rerank.json

# 2) 与基线做配对 bootstrap 检验
python -m wealth_rag.evaluation --compare-with eval/runs/baseline.json

# 3) 切分侧诊断（与端到端指标互补）
python docs\audit\verify_fix.py          # 标题覆盖率 / 面包屑深度 / 污染块 / 章级覆盖
python docs\audit\test_outline.py        # 章级大纲重建回归
python docs\audit\test_heading_rules.py  # 标题规则回归
```

**评估集行格式**：

```jsonc
{"id":"q007","query":"存款保险的偿付限额是多少","category":"数值",
 "gold_headings":["(二) 实行限额偿付"],"must_not":[],"note":"答案含 50 万元"}
```

- `category` 以 `负例` 开头即视为**不可答**；
- `gold_headings` 为空且 `category` 非负例 → 视为标签缺失（校验脚本会报错）；
- 旧格式 `{"query":..., "relevant":[...]}` 仍可读，但**只作兜底**，因为它对切分不敏感。

## 8. 已知局限

1. **评估集 70 条，规模仍偏小**：±13pp 量级的 CI 意味着只测得出大改动。可借用 PPI
   （prediction-powered inference）思路：把「LLM 对全库 664 块的判定」当未标注预测，
   用少量人工标注做 rectifier，在不增加人工的前提下收窄 CI。
2. **`q001`/`q067` 的 `must_not: ["目录"]` 当前落空**（目录已被剔除）——这是目标状态，
   但意味着**目录类污染没有活的守卫**，需要靠回归测试而非评估集来盯。
3. **无分级相关性标注**：nDCG 用的是二值增益。若要区分"完全命中/部分命中"，
   需在评估集里加 `gain` 字段。
4. **未做 `ParentCoverage@k`**：缺 gold 父子映射标注（109 个父块可全量人工标注）。
5. **拒答只报单点**：尚未做阈值扫描与 risk–coverage 曲线。
6. **未做多重比较校正**：当前只有 1 组对比（rerank on/off），配置一多必须加 Holm。
