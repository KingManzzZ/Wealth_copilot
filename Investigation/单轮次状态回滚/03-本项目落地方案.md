# 03 · 实现说明（快照差异 + 撤回）

> 这一篇描述**已经落地的实现**，不是备选方案。
> 一句话：每轮开始/结束各给 5 张业务表拍一次快照，差异写进 `turn_writes`；
> 撤回时按差异逆序还原，并把这一轮的消息标记为撤回。

## 3.1 数据模型

### `messages` 新增三列

| 列 | 作用 |
|---|---|
| `turn_id` | 一轮的 id，用户消息与助手消息共用；撤回按它定位 |
| `withdrawn` | 撤回标记。撤回后**不进上下文、不出现在消息列表**，但行保留（审计） |
| `withdrawn_at` | 撤回时间 |

读取路径只有一处过滤：`services/conversations.get_conversation_messages()` 加
`AND withdrawn = 0`。API 与模型上下文都走它，所以不会出现"界面没了、模型还记得"。

### `turns`

```sql
CREATE TABLE turns (
    turn_id         TEXT PRIMARY KEY,
    conversation_id INTEGER NOT NULL,
    status          TEXT NOT NULL,   -- running | completed | interrupted | withdrawn
    created_at      TEXT NOT NULL,
    finished_at     TEXT
);
```

- 轮次开始写 `running`，结束写 `completed` / `interrupted`，撤回写 `withdrawn`；
- 目前**没有**崩溃恢复：进程中途挂掉会留下 `running`（见 04 的待办）。

### `turn_writes`（差异日志）

```sql
CREATE TABLE turn_writes (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    turn_id         TEXT NOT NULL,
    conversation_id INTEGER NOT NULL,
    table_name      TEXT NOT NULL,
    pk_json         TEXT NOT NULL,   -- 主键 dict
    op              TEXT NOT NULL,   -- insert | update | delete
    before_json     TEXT,            -- insert 时为 NULL
    after_json      TEXT,            -- delete 时为 NULL
    status          TEXT NOT NULL DEFAULT 'applied',
    detail          TEXT,
    created_at      TEXT NOT NULL,
    compensated_at  TEXT
);
```

## 3.2 为什么用快照差异，而不是在每个工具里埋点

最初计划是在 9 个写函数里各加一段 `before/after`。实际改成：

- 轮次开始：`capture()` 读 5 张表 → `{表: {主键: 行}}`；
- 轮次结束：再 `capture()` 一次 → `diff()` 出 insert / update / delete；
- 变化行写进 `turn_writes`。

三个好处：

1. **不改任何工具/service**，不会漏记（工具怎么写都跑不出这 5 张表）；
2. 天然覆盖"一轮写了多张表"；
3. 差异只存变化的行，体积可控。

代价是每轮多两次全表读。个人账本（当前 184KB）可以忽略；若将来数据量大到
百万行，再退回"逐工具埋点"或"只快照被写的表"。

**参与快照的表**：`transactions`、`assets`、`debts`、`goals`、`basic_info`。
`messages / conversations / turns / turn_writes` 不在其中——它们是对话与审计本身。

## 3.3 轮次生命周期

```
POST /api/chat
  ├─ 生成 turn_id（前端传或后端补）
  ├─ 落库用户消息（带 turn_id）
  ├─ turn_state.begin(turn_id, conversation_id)   ← 拍轮前快照（失败则本轮不可撤数据）
  ├─ worker 线程跑 chat_stream …（工具照常写库）
  └─ finally:
       落库助手消息（带 turn_id + interrupted）
       turn_state.finish(...)                    ← 算差异 + 写 turn_writes + 更新 turns
       mark_done（撤回接口这时才能读到完整写集）
```

## 3.4 撤回接口

```
POST /api/conversations/{id}/withdraw   { "turn_id": "..." }
```

流程（`services/turn_state.withdraw`，一个 SQLite 事务）：

1. **停**：`chat.stop_turn()`——若该会话还在生成，取消并等收尾（最多 5s）；
2. **定位与校验**：
   - 按 `turn_id` 找到这一轮的第一条消息 → 找不到则 404；
   - `truncate=true`（界面「↩」，默认）：取它和它之后的**全部未撤回消息**（后面的对话建立在这一轮之上，一起撤）；
   - `truncate=false`（模型提案确认后）：**只撤这一轮**，保留后面的对话（用户是在新的一轮里说"撤回刚才那笔"，不能把他刚说的话也删了）；
   - 目标轮 `status == running` → 409（还没收尾）；
3. **核对**：对每条 `applied` 的写，比较"当前行"与记录里的 `after`：
   - 插入 → 行应存在且等于 after；
   - 更新 → 行应存在且等于 after；
   - 删除 → 行应不存在；
   任何一条不符 → **整体放弃**，返回 409 + 冲突明细（不覆盖用户的修改）。
4. **还原**：`insert` 删行、`update` 用 before 覆盖、`delete` 用 before 重新插入；
   同时把 `turn_writes.status` 置 `compensated`；
5. **撤消息**：本轮所有消息 `withdrawn=1`；
6. **回标题**：取撤回后第一条用户消息重算（撤掉第一轮时标题要跟着回退）；
7. 提交，返回：

```json
{
  "turn_id": "…",
  "withdrawn_messages": 4,
  "turns_withdrawn": 2,
  "user_text": "记一笔午餐 35",
  "rollback": { "compensated": 1, "noop": 0, "conflicts": 0, "failed": 0 }
}
```

`user_text` 用于前端把原话回填输入框——这就是"恢复未发送状态"。

## 3.5 模型提案：`request_withdraw`（只读）

用户在对话里说「撤回 / 撤销 / 刚才那轮不要了」时，模型调用的不是撤回本身，而是一个
**只读提案工具**：

- 返回 `{proposal:"withdraw_turn", turn_id, summary, affected_turns, affected_writes, ...}`；
- **不删任何消息、不改任何数据**；
- 前端据此渲染「撤回确认」卡片，用户点「确认撤回」才调 `POST /withdraw`（`truncate=false`）。

工具签名里没有 `conversation_id`：worker 线程在生成前把 `(conversation_id, 当前轮 id)`
绑定到 `core/agent/turn_context.py` 的线程本地，工具据此把"上一轮"解析成具体 `turn_id`。

## 3.6 冲突判定为什么用"整行相等"

`after_json` 是**写完之后立刻读回**的整行（含服务端写的 `updated_at`）。
之后任何人改了这一行，`updated_at` 必变 → 比较不相等 → 判定冲突。

- 不会误删用户的后续修改；
- 不会因为 `35` / `35.0` 这类数字表示差异误判（比较时数值统一按 float）。

## 3.7 前端

| 变化 | 说明 |
|---|---|
| 撤回按钮 | 只在**最后一轮回答**下显示；生成中/停止中不显示 |
| 确认 | 原生 `confirm`，文案说明"对话与数据都会撤销" |
| 成功后 | 用服务端消息覆盖本地 → 消息消失、原话回填输入框、聚焦 |
| 失败后 | 输入框上方显示红色提示（如"只能撤回最后一轮""数据已被修改"） |
| 数据刷新 | 撤回成功广播一次 `chat-turn-completed`，仪表盘/流水自动重拉 |

## 3.9 已知限制与扩展点

| 限制 | 影响 | 扩展方式 |
|---|---|---|
| 撤回会截断之后的对话 | 不能只删中间一轮而保留后面（会前后矛盾） | 若要"只删一条消息"，需另做消息级删除 |
| 冲突时整体放弃 | 用户手工改过就撤不了 | P1 可给"仍然恢复"选项，或只撤未冲突的条目 |
| 无崩溃恢复 | 进程崩溃会留 `running` | 启动扫描 `turns.status='running'`，用 `turn_writes` 还原或标记 |
| 外部副作用不支持 | 目前没有支付/邮件 | 接入时给写类型加 `compensable` 标记，不可撤的必须走审批 |
| 快照全表读 | 数据量大时变慢 | 只快照"本轮访问过的表"，或改为逐工具埋点 |
