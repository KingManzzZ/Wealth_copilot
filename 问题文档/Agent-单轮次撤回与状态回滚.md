# Agent · 单轮次撤回与状态回滚

> **一句话**：在任意一条用户消息下面点「↩」，二次确认后，**这条消息及其之后的全部对话被移除**，
> 这些轮次写进账本的数据也一并还原；确认后不可恢复。
>
> **状态**：已实现（后端 + 前端 + 测试）。
> **范围**：`backend/core/services/turn_state.py`、`backend/api/routes/conversations.py`、
> `backend/core/database/schema.py`、前端 `useChat` / `chat-panel` / `message-bubble`。
> **关联**：[取消（停止生成）](./Agent-生成中止与取消.md)、
> [调研与方案](../Investigation/单轮次状态回滚/README.md)。

## 一、用户怎么操作

1. 每条**用户消息**气泡下方有一个圆形「↩」图标按钮（助手回答下面没有，因为撤回的单位是"轮"）；
2. 点击后弹出确认框，文案会写清**不可恢复**与**会撤掉几轮**：

   > 撤回后不可恢复。
   > 将从这条消息起，移除它及之后的 N 轮对话，并还原这些轮次写入账本的数据。

3. 确认后：
   - 这条消息与它之后的对话从界面上消失；
   - 这一轮的用户原话回到输入框（可以改完再发）；
   - 仪表盘 / 流水抽屉自动刷新；
   - 若数据无法安全还原（见第四节），界面显示红色原因，**不做任何修改**。

> 生成中 / 停止中不显示撤回按钮——那时 worker 还在写，撤回会与它抢同一批数据。

## 二、为什么是"任意一轮 = 从这轮起全部撤回"

后面的对话是**建立在这一轮之上**的。如果只删中间一轮、保留后面，上下文会出现
"用户在追问一个已经不存在的回答"，模型会答得莫名其妙。所以语义定为：

> 撤回第 N 轮 = 回到"第 N 轮还没发送"的状态，第 N 轮及之后全部撤回。

更早的轮次不受影响。

## 三、后端做了什么（按执行顺序）

```
POST /api/conversations/{id}/withdraw  { turn_id }
```

1. **先停**：该会话若还在生成，取消并等它收尾（最多 5 秒）；停不下来返回 409。
2. **定位**：按 `turn_id` 找到这一轮的第一条消息，取出**它和它之后的全部未撤回消息**。
3. **收集写集**：这些轮次在 `turn_writes` 里状态为 `applied` 的记录，按 id 排序。
4. **逐条核对**（在同一个 SQLite 事务里）：
   - 本轮插入的行：当前应存在，且与记录里的 `after` 完全一致；
   - 本轮的更新：当前应等于 `after`；
   - 本轮的删除：当前应不存在。
   只要有一条不符（说明之后被人改过），**整体放弃**并返回 409 + 冲突明细。
5. **还原**（逆序，后写的先撤）：插入的删掉、更新的写回 `before`、删除的按原 id 插回去。
6. **撤消息**：从这一轮的第一条起，全部置 `withdrawn=1`（不物理删除，保留审计）。
7. **收尾**：受影响轮次置 `turns.status='withdrawn'`；重算会话标题（撤掉第一轮时标题回退）；
   返回摘要。

响应示例：

```json
{
  "turn_id": "…",
  "withdrawn_messages": 4,
  "turns_withdrawn": 2,
  "user_text": "记一笔午餐 35",
  "rollback": { "compensated": 1, "noop": 0, "conflicts": 0, "failed": 0 }
}
```

`user_text` 就是回填输入框的内容。

## 四、数据是怎么记下来的（不用改任何工具）

每一轮：

- **开始前**：给 5 张业务表拍快照（`transactions / assets / debts / goals / basic_info`）；
- **结束后**：再拍一次，对比出新增 / 修改 / 删除，写进 `turn_writes`。

这样**不需要在每个写工具里埋点**，也不会漏记——工具怎么写都跑不出这 5 张表。
代价是每轮两次全表读；账本只有 184KB，可以忽略。

## 五、数据模型

| 表 | 作用 |
|---|---|
| `messages` + `turn_id` | 一轮的用户消息与助手消息共用同一个 id，撤回按它定位 |
| `messages` + `withdrawn` / `withdrawn_at` | 撤回标记。撤回后**不进模型上下文、不出现在消息列表**，行保留 |
| `turns` | 轮次生命周期：`running / completed / interrupted / withdrawn` |
| `turn_writes` | 差异日志：表、主键、`op`、`before`、`after`、`status` |

读取侧只有一处过滤：`get_conversation_messages()` 的 `AND withdrawn = 0`。
API 与模型上下文都走它，所以不会出现"界面没了、模型还记得"。

## 六、失败与提示

| 情况 | HTTP | 界面提示 |
|---|---|---|
| 轮次不存在 / 已撤回 | 404 | 这一轮不存在或已撤回 |
| 这一轮还在收尾（`running`） | 409 | 这一轮尚未收尾，暂时不能撤回 |
| 数据之后被改过 | 409 | 这些轮次写过的数据之后被修改过，已放弃撤回（不会覆盖你的修改） |
| 会话不存在 | 404 | 会话不存在 |

**冲突时整轮放弃**是刻意的：宁可撤回失败，也不覆盖用户后来的手工修改。

## 七、测试

```powershell
cd backend
python tests/rollback/run_tests.py            # 9 个用例（路由层缺依赖时跳过）
python tests/rollback/run_tests.py -k truncate
```

装齐 `fastapi + httpx` 后：**11 通过 / 0 失败 / 0 跳过**。覆盖：

| 用例 | 覆盖 |
|---|---|
| 插入 / 更新 / 删除的还原 | 三种写操作都能还原（删除的按原 id 恢复） |
| 无写入轮次 | 只撤对话，数据本来没变 |
| 撤回中间一轮 | 这轮及其之后消失，更早的保留，写集按逆序撤 |
| 冲突 | 数据被改过 → 整体放弃、不覆盖、消息不撤 |
| 重复撤回 / 未知轮次 | 404 |
| 上下文隔离 | 撤回的轮次不进模型上下文 |
| 路由 | 200 / 404、返回体、消息列表为空 |
| 会话不存在 | 404 |

所有用例强制走一次性数据库（`_support.temp_database()`），不碰 `backend/db/data.db`。

## 八、和"停止生成"的区别

| | 停止生成（取消） | 撤回（本文） |
|---|---|---|
| 作用对象 | 进行中的生成 | 已存在的一轮对话 |
| 结果 | 不再输出、保留已生成内容 | 消息消失 + 数据还原 |
| 数据 | **不回滚**（已写入的保留） | 回滚 |
| 可恢复 | 可以继续追问 | **确认后不可恢复** |
| 接口 | `POST /api/chat/cancel` | `POST /api/conversations/{id}/withdraw` |

## 九、运维

- 升级后**重启后端**：`schema.py` 会自动给旧库补 `turn_id / withdrawn / withdrawn_at` 三列，
  并创建 `turns` / `turn_writes` 两张表（幂等）。
- 前端 dev 重载即可；新增按钮不需要额外配置。
- 旧对话（升级前产生的）没有 `turn_writes`，撤回会返回 409"尚未收尾"，属预期。

## 十、已知限制与后续

| 限制 | 说明 | 后续 |
|---|---|---|
| 不能只撤一条消息 | 撤回单位是"轮"（用户消息 + 助手回答） | 若需要，可加"只撤回答、重答"功能 |
| 崩溃恢复未做 | 进程崩在轮次中途会留下 `turns.status='running'` | 启动扫描并标记/还原 |
| 不可恢复 | 确认后没有"撤销撤回" | 可加 5 秒内撤销（用 `after` 重放） |
| 外部副作用 | 目前没有支付/邮件 | 接入后需给写操作加"可补偿"标记，不可撤的走审批 |
| 撤回后模型不知情 | 撤回的轮次不进上下文 | 可选：注入一句"上一轮已撤回" |
