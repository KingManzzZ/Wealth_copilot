## 元教训

### 事故的元教训（第一阶段）

**15 个问题中，有 14 个自 2026-10-10 初始提交起就已存在，却直到 5 天后的系统性审查才被发现。**
根因不是"代码写错"，而是**缺少对产物本身的量化检查**：

- 有单元测试，但没有**产物检查**（切出来的块到底长什么样？）
- 有评估指标，但**粒度错配导致失敏**（P0-7）
- 有 README，但没有**文档与实现的比对**

**结论**：对数据密集型系统，**"检查产物的分布"比"检查代码的逻辑"更能发现问题**。
建议把 `docs/audit/` 下的诊断脚本纳入常规回归流程。

### 「看起来能用」的普遍性（第二阶段）

三个例子，三种不同的"看起来能用"：

| 问题 | 看起来 | 实际 |
| :--- | :--- | :--- |
| P0-10 | 文档说"评估是文档级的，需另建 chunk 级评估集" | 代码早已是 chunk 级，且有 70 条现成标注 |
| P0-11 | 评估框架指标齐全，能评估检索质量 | 不采集分数，**结构上无法回答"阈值该定多少"** |
| P0-12 | 有 gold 标注，能算相关性 | 二值标注，**结构上无法校准 `rerank_floor`** |

**共同点：都是"能力存在但分辨率不够"** ——不是缺失，而是**粒度/维度不对**。

**另一个反复出现的模式：「静默失效」。** 第二阶段有 5 处"不报错但功能不生效"：

| 问题 | 静默表现 |
| :--- | :--- |
| P0-10 | 文档错误断言不报错，让人做已做完的工作 |
| P1-7 | 未标注的默认 0 被当成"确认无关" |
| P1-9 | `recall_w` 未设置 → 渲染分支静默跳过 |
| P2-12 | 去重键退化到块级 → 去重静默失效 |
| P2-9 | 文档路径过期 → 复制命令后报"路径不存在"，需自行推断原因 |

**通用对策**：可选分支要区分"未启用"与"未设置"；回退路径要保持与主路径相同的语义保证；
引用（文档/配置）要能被校验。

### 读代码不能替代跑代码（第三阶段）

**6 项失败，没有一项是靠阅读代码发现的。更要紧的是：对其中 4 项的第一次分析是错的。**

| 失败项 | 第一次分析 | 实际原因 |
| :--- | :--- | :--- |
| 派生 4 项 | "测试夹具写错了文件名" | ✅ 方向对，但**真实原因是函数硬编码读 `pool.jsonl`**，且它静默降级 |
| 低覆盖率 | "覆盖率边界算错了" | ✅ 方向对，但真实原因是**门槛 30% 与 33.3% 只差一个候选** |
| 保守阈值 | "保守值**可能**略高于主值（浮点抖动）" | ❌ **完全错**——设计上不可能更高，是**断言方向写反** |
| 输出顺序 | "runner 的缓冲问题" | ⚠️ 部分对，根因是 **rich 绕过 print 缓冲** |

在无法执行的环境里说"逐行重读核对过"，**给了错误的确定性**。准确表述应该是：

> 我无法验证这些代码能否运行。以下结论仅基于静态阅读，
> **其中关于"逻辑是否正确"的每一条判断都未经证实**。

### 形态遗留比代码缺陷更难发现（第四阶段）

第四阶段三个问题，**没有一个是"代码写错了"**：

| 问题 | 代码对不对 | 真正的毛病 |
| :--- | :--- | :--- |
| P2-25 | ✅ 全对 | 依赖声明在两个项目里各写一份 |
| P2-26 | ✅ 全对 | 导入依赖一次历史安装 |
| P2-27 | ✅ 全对 | 临时方案的残留目录 |

**它们都不会让任何测试失败，也不会在开发机上暴露。** 融合一个模块时，要检查的不只是

## 附：不建议做的事（有明确反证）

| 方向 | 反证 |
| :--- | :--- |
| **引入语义分块** | arXiv 2410.13070《Is Semantic Chunking Worth the Computational Cost?》结论：计算成本未被稳定的性能提升所证明 |
| **引入 LLM chunk 上下文/摘要** | Anthropic 官方明确说明「给 chunk 加通用文档摘要收益非常有限」；Contextual Retrieval 成本约 $1.02/百万文档 token |
| **换更大模型** | 第一阶段的问题在切分层与解析层，换模型解决不了标题缺失 |
| **迁移到 Qdrant 原生 BM25** | 当前自实现 jieba + 中文 2-gram **恰好规避了** Qdrant BM25 默认 English stemming/stopwords 对中文静默劣化的坑；若要迁移必须配置 `tokenizer: "multilingual"` + 关闭英文 stemming |
| **把 RAG 当纯 pipeline（每轮强制检索）** | 本项目 Agent 有 24 个工具、大量提问不需要知识库；强制检索会白加 1~3s 且塞入不相关内容。详见 [`../Investigation/RAG触发策略和rerank/01-when-to-trigger.md`](../Investigation/RAG触发策略和rerank/01-when-to-trigger.md) |
