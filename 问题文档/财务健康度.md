# 财务健康度 · 实现说明

> **一句话**：仪表盘的"财务健康度"不再写死，改成 5 维实时评分
> （储蓄、应急、负债、目标、资产配置），缺失维度剔除后重新归一化。
>
> **状态**：已实现（后端 + 前端文案 + 12 条测试）。
> **调研依据**：[`../Investigation/财务健康度/01-指标与算法调研.md`](../Investigation/财务健康度/01-指标与算法调研.md)。

## 一、改动前的问题

`backend/api/routes/dashboard.py` 里是一个模块级常量：

```python
HEALTH = {
    "overall": 0,          # 总分 0
    "grade": "B",          # 却给 B
    "dimensions": [
        ...,
        {"name": "目标进度", "score": 75, "advice": "测试111"},  # 测试残留
    ],
}
```

- 不读库、不调 service，永远不变；
- `overall=0` 与 `grade="B"` 自相矛盾；
- 前端 `HealthScore` 只是展示，用户改资产/记账都不会影响它。

## 二、现在的评分

### 2.1 五个维度

| 维度 | 权重 | 公式 | 评分映射 |
| :--- | ---: | :--- | :--- |
| 储蓄率 | 25% | 近 3 个月 `(收入−支出)/收入` 均值 | 5%→0，30%→100 |
| 应急储备 | 20% | 现金类资产 / 月均支出（月数） | 0→0，6 个月→100 |
| 负债健康 | 25% | `0.5×DTI + 0.5×负债资产比 + 0.2×高息占比`（无利率数据时 `0.6/0.4`） | DTI 15%→100、50%→0；负债率 20%→100、70%→0；高息占比 10%→100、50%→0 |
| 目标进度 | 15% | `实际进度 − 按时间应达进度`（无 `created_at` 时退回"缺口 vs 月结余"） | 在轨 50 分，超前 50%→100，落后 50%→0；过期未完成→20 |
| 资产配置 | 15% | `|高风险占比 − 风险目标|` | 完全匹配→100，偏离 50%→0 |

风险目标：`conservative=20%`、`balanced=40%`、`aggressive=60%`。

### 2.2 总分与等级

```text
weighted = Σ(score×weight) / Σ(weight)        # 缺失维度剔除并重新归一化
penalty  = min(30, 10 × 低于 40 分的维度数)
overall  = clamp(weighted − penalty, 0, 100)
grade    = A≥85 / B≥70 / C≥55 / D<55
```

**为什么要短板惩罚**：负债 5 分、其他 90 分，加权平均仍有 70+，但这个人实际很脆弱。
财务健康是"最弱一环"问题。

### 2.3 数据不足

- 某个维度算不出来 → **不返回该维度**（不用 0 填充）；
- 可用维度 < 2 → `overall=0`、`data_quality="insufficient"`；
- 2~4 维 → `data_quality="partial"`；5 维 → `"full"`。

## 三、数据来源

| 数据 | 来源 | 说明 |
| :--- | :--- | :--- |
| 收入/支出 | `transactions` 按月聚合（`cashflow.py`） | 唯一数据源，不存汇总 |
| 现金类/自住房/高风险资产 | `assets.asset_type` | 新增字段：`cash / investment / property / other` |
| 月供/剩余本金/利率 | `debts.monthly_payment / remaining / annual_rate` | `annual_rate` 新增，小数（0.05=5%） |
| 目标 | `goals.target / current / deadline / created_at` | `created_at` 由 `list_goals` 暴露 |
| 风险承受能力 | `basic_info.risk_tolerance` | `conservative / balanced / aggressive` |

### 3.1 兼容旧数据

- `assets.asset_type` 缺失/为 `other` → 按名称关键词推断（现金/活期/货币/存款→cash；
  股票/基金/ETF…→investment；房/住宅/商铺→property）；
- `debts.annual_rate` 为 `NULL` → 按"无高息"处理，不参与高息扣分；
- `goals.created_at` 一定有默认值；老数据也走时间进度。

### 3.2 两个刻意的口径

1. **储蓄率用近 3 个月均值**，不是单月——年终奖/装修/看病会让单月失真；
2. **应急资金只算 `cash` 类型**，自住房、股票、长期理财不算——否则会高估韧性。

## 四、API 契约

`GET /api/dashboard` 的 `health`：

```json
{
  "overall": 69,
  "grade": "C",
  "dimensions": [
    {"key": "saving", "name": "储蓄率", "score": 100, "advice": "..."},
    {"key": "emergency", "name": "应急储备", "score": 28, "advice": "..."},
    {"key": "debt", "name": "负债健康", "score": 72, "advice": "..."},
    {"key": "goal", "name": "目标进度", "score": 100, "advice": "..."},
    {"key": "allocation", "name": "资产配置", "score": 100, "advice": "..."}
  ],
  "data_quality": "full"
}
```

- 前端 `FinancialHealth` 只读 `overall / grade / dimensions[].name/score/advice`，
  `key` 与 `data_quality` 是**额外字段**，前端可忽略；
- `dimensions` 可能少于 5 条（数据不足时），前端是动态遍历，不能假设固定 5 条。

### 4.1 详情抽屉

卡片右下角「查看各项原始数据」打开右侧抽屉（`HealthDetailDrawer`）：

- 数据来自 `GET /api/dashboard/health-detail`，**不进 dashboard 主请求**；
- 每个维度展示：分数、advice、若干 `metrics`（label / 实际值 / 目标线 / `good|warn|bad` / note）；
- 例：应急储备 → `1.7 个月`，目标 `≥ 6 个月`，`bad`，备注"现金类 6.0 万 ÷ 月支出 3.6 万"；
- `data_quality` 在顶部显示"数据完整 / 部分数据缺失 / 数据不足"；
- 加载中有骨架、失败有重试；Esc / 点遮罩关闭（Radix Dialog）。

覆盖：

| 用例 | 覆盖 |
| :--- | :--- |
| 空库 | overall=0、dimensions=[]、insufficient |
| 完整数据 | 5 维齐全、分数 0~100、每维有 advice、full |
| 详情结构 | 每维有 metrics（label/value/target/status），主接口不带 metrics |
| 储蓄率边界 | 40%→100；0%→0 |
| 应急边界 | 6 个月→100；0 元→0 |
| DTI | 高月供分数更低 |
| 高息负债 | 24% 利率分数更低 |
| 目标时间进度 | 时间过半/进度过半→约 50；超前→高分；过期→20 |
| 资产配置 | 稳健型 40%→100；积极型 40%→60 |
| 缺少风险测评 | 不给资产配置分，data_quality=partial |
| 资产类型推断/覆盖 | 名称推断 + 显式 `asset_type` 优先 |
| 利率保留 | 更新债务不传利率时保留原值 |
| 等级边界 | 85/70/55 分档 |

每个用例一个一次性 SQLite 库（`_support.temp_database()`），不碰 `backend/db/data.db`。

## 六、已知限制

| 限制 | 说明 | 后续 |
| :--- | :--- | :--- |
| 资产类型靠推断 | 旧数据没有 `asset_type`，只能关键词推断 | 前端/工具写入时逐步补 `asset_type` |
| 无保险维度 | 没有保险表 | 需要时新增保障表，再加一维 |
| 无征信/负债利率全覆盖 | `annual_rate` 可选，未填按无高息处理 | 录入时提示填写 |
| 中国口径未完全本地化 | DTI 阈值仍可配置；房贷/自住房/社保需按地区校准 | 做成配置项 |
| 健康度不落库 | 派生值，每次实时算 | 保持（避免第二份真相） |
